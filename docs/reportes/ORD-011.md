# Informe ORD-011 — Optimización de consumo de XHANNIZER0 (CPU/GPU/RAM) + Modo ligero

- **Orden:** `ORD-011` (`v2.4.0`)
- **Fecha:** 2026-11-27
- **Solicitud de commit:** `APR-014` (pendiente de aprobación, sin push ni cambio de versión)

## Cambios realizados

1. **Monitor en vivo de costo casi cero (`src/backend/hardware.js` y `src/renderer/js/app.js`):**
   - CPU y RAM continúan en Node nativo (`os.cpus()` delta + `os.freemem()` / `os.totalmem()`, **0 procesos PowerShell**).
   - Añadida caché de corta duración para consultas lentas: disco (`DISK_CACHE_TTL_MS = 8000` ms) y GPU `nvidia-smi` (`GPU_CACHE_TTL_MS = 7500` ms), omitiendo por completo lanzar `nvidia-smi` cuando el hardware escaneado no tiene GPU NVIDIA.
   - Elevado el intervalo de polling del renderer en `syncLiveMonitorSchedule()` de `2.5 s` a **`3 s`** (`Actualizando cada 3 s`).
2. **Render liviano para todos (`src/renderer/styles/app.css`, `chrome.css`, `motion.css`):**
   - Aplicado `content-visibility: auto; contain-intrinsic-size: auto 96px;` a las tarjetas de listas largas (`.app-grid .app-card`, `.driver-list .driver-card`, `#drivers-list .driver-card`, `#upgrades-list .driver-card`, `#emu-grid .app-card`).
   - Eliminados los `will-change: transform, opacity;` permanentes en elementos en reposo (`#xh-batch-dock`, `.backup-sheet`, `.spotlight-box`, `#xh-audit-drawer`, `.xh-svc-pop`, `.xh-side-hover-pill`, `.xh-side-active-bar`).
3. **Modo ligero / Bajo consumo (`data-lite="true"`):**
   - `tokens.css`: fondos sólidos limpios para tema oscuro y claro bajo `:root[data-lite="true"]` y desactivación total `-webkit-backdrop-filter: none !important; backdrop-filter: none !important;`.
   - `motion.css`: desactiva brillo especular, shimmer infinito de barras de progreso, elevaciones/sombras en hover, ondas táctiles, transiciones y pill flotante cuando `data-lite="true"` está activo.
   - `motion.js`: detecta `data-lite="true"` y desactiva los listeners `pointermove`, bucles `requestAnimationFrame` de tilt 3D, glow 1 px, botones magnéticos, ripple y cascadas; expone `XhMotion.setLiteMode(active)` para cancelar de inmediato cualquier rAF activo.
   - `index.html` y `app.js`: añadido selector en **Ajustes** (`Automático` / `Activado` / `Desactivado`, persistido en `localStorage` bajo `xh_lite_mode`) con texto de estado dinámico (`#settings-lite-hint`). En `Automático`, se activa en PCs modestas (`ramGb <= 8`, `threads <= 4`, sin GPU dedicada o `prefers-reduced-motion: reduce`) y pausa el monitor en vivo por defecto salvo que el usuario lo reanude manualmente.
4. **Arranque escalonado (`src/renderer/js/app.js`):**
   - En `boot()`, primero ejecuta el escaneo principal de hardware + datos livianos (`loadEmulators`, `refreshBackupCount`), evalúa el Modo ligero y pinta *Resumen*; después escalona secuencialmente `loadCatalog` (+250 ms), `loadStartupApps` (+350 ms), `loadWindowsAudit` (+450 ms) y `liveCheckDrivers` (+500 ms) para evitar lanzar múltiples procesos PowerShell pesados a la vez.
5. **Traducciones EN y pruebas (`src/renderer/js/i18n-en.js`, `tests/unit.test.js`):**
   - Añadidas traducciones EN para Modo ligero y polling de 3 s.
   - Añadido test en `tests/unit.test.js` cubriendo `shouldAutoEnableLiteMode`, TTL de caché (6–8 s), lectura en caché rápida de `getLiveSystemMetrics`, reglas CSS `data-lite="true"` / `content-visibility: auto` y soporte en `motion.js`.
